# Entrega 1 — Criar processos

**Vale 0,8** · **Prazo: 02/10/2026** · em grupo

Fazer o shell executar um comando: criar o processo, trocar o programa dele,
esperar terminar e guardar o código de saída.

---

## O que fazer

Preencher `executar_comando()` em `src/executar.c`. Sem redirecionamento e sem
cano — isso é da Entrega 2.

O caminho é sempre o mesmo, e vale decorar a forma:

```c
pid_t pid = fork();          /* agora existem DOIS processos */
if (pid == 0) {
    /* aqui é o FILHO: ele troca de programa e não volta */
} else {
    /* aqui é o PAI: ele espera */
}
```

```bash
make verificar E=1
```

## O que precisa estar funcionando

- Comando externo roda e o shell **espera** ele terminar.
- Comando que não existe: mensagem na saída de erro e **código 127**.
- O embutido `codigo` mostra o código do último comando.
- O shell **nunca** morre porque o comando falhou.

## As três armadilhas desta entrega

**`execvp` que volta é `execvp` que falhou.** Quando dá certo, ele não retorna
nunca — o programa foi substituído. Se a linha depois dele executou, o comando
não existia. É ali que sai o 127.

**`_exit`, não `exit`, no filho.** O filho herdou os buffers do pai. `exit`
esvazia esses buffers de novo, e o que o pai ainda não imprimiu sai duplicado.
Esse defeito não aparece em teste nenhum até aparecer no lugar mais estranho.

**O filho precisa reagir ao Ctrl-C.** O shell ignora o `SIGINT` para não
morrer junto — e o filho **herda esse ignorar**. Sem `signal(SIGINT, SIG_DFL)`
antes do `execvp`, nenhum comando seu poderá ser interrompido. Isso só é
cobrado na Entrega 3, mas o lugar de resolver é aqui.
